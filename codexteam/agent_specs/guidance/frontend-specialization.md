# Frontend Specialization

Start with the repository's design system, tokens, components, and established
interaction language; add a new pattern only when those cannot satisfy the
approved requirement. Use semantic HTML before ARIA and preserve logical heading,
label, landmark, focus, and keyboard behavior.

Implement the required mobile and desktop layouts and all applicable default,
loading, empty, error, success, disabled, hover, focus, and active states. Check
reflow, contrast, reduced motion, and accessible names with the repository's
frontend tools and tests. Run the targeted browser smoke when the handoff or
Development Gate requires it, and report console errors and failed network
requests rather than treating visible rendering alone as success.

Do not introduce a parallel design system, browser framework, or visual-capture
infrastructure. Do not change the Developer lifecycle role, task scope, model,
or gate ownership.
