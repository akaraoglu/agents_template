# Task T002: Design the code and project architecture

## Objective

Turn approved requirements into the smallest complete architecture and repository design needed for implementation.

## Responsible AI

`architect-01` - architect role; default `qwen36-27b` profile with high reasoning.

## Context

Read `PROJECT.md`, `BRIEF.md`, `IMPLEMENTATION_PLAN.md`, accepted decisions, `management/TEST_GATES.toml`, the existing `ARCHITECTURE.md`, and `.codexteam/skills/architecture-design.md`. Inspect only source and configuration needed to understand an existing system.

## Scope

System boundaries, repository layout, component responsibilities, dependency direction, public contracts, data flows, trust boundaries, failure handling, deployment, compatibility, migration, and test architecture.

## Allowed Paths

`ARCHITECTURE.md`, `docs/architecture/`, `docs/decisions/`, and scoped architecture evidence under `results/`. Do not modify source, tests, canonical lifecycle state, or Git state.

## Required Outputs

An implementation-ready architecture, exact repository map, requirement traceability, explicit gate coverage, risks, and material ADR proposals.

## Verification

Confirm every component and dependency serves an approved requirement, important failure and security boundaries are explicit, and the Developer can implement without inventing structural decisions.

## Done Criteria

The Project Lead accepts the architecture and records any accepted ADRs before implementation begins.

## Stop Conditions

Stop when requirements conflict, an unapproved dependency is necessary, or the existing implementation contradicts the proposed boundary.

## Reporting

Return an architecture draft, alternatives, risks, and approval questions. Never implement or approve your own design.
