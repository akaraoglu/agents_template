# Pull Request Description

## Summary

Describe the outcome and user-visible behavior in two to four sentences.

## Motivation

Explain the problem, requirement, or linked issue this change addresses.

## Scope

- Included changes
- Explicit non-goals

## Design

Summarize material decisions and alternatives when they aid review.

## Compatibility and Operations

- API, schema, migration, configuration, or dependency impact
- Rollout and rollback considerations
- Security, privacy, performance, or observability impact

## Verification

- Commands run and observed results
- Manual or user-visible checks
- Checks not run and why

## Evidence

- Screenshots, recordings, logs, benchmarks, or artifact links when relevant

## Risks and Review Focus

- Known risks and residual uncertainty
- Areas requiring particular reviewer attention

## Follow-ups

- Intentionally deferred work
- Open decisions
